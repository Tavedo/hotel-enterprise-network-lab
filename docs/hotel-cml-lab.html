1 · What it is

The brief is a real property, not a routing exercise: guests get internet but never the hotel LAN; appliances (phones, door locks) reach their server but never the internet; point-of-sale reaches its payment server and the card processor but nothing else; and if a core switch, an uplink, or an ISP dies, the network keeps running with no human touch.

AreaDesign
L3 coreMultilayer switch, SVIs per VLAN, ip routing, routed /30 to the edge
SegmentationFour-tier ACL model — guest (internet-only), voice & IoT (server-only), F&B/POS (PMS + payment, no lateral); all default-deny, proven with live pings
Internet edgeEDGE-R1 PAT behind one public IP; ISP-R1 + public server as "the internet"
Core HAHSRPv2 per VLAN, priority + preempt, object tracking on the uplink; STP root aligned to the active core
WAN HADual transit to the edge + IP SLA + tracked static failover
HardeningSSH-only with a management ACL, port-security, BPDU Guard, unused ports parked in a black-hole VLAN
RoadmapEtherChannel (LACP), dual-ISP, a second edge router for the last SPOF

3 · Topology

  internet -- ISP-R1 -- EDGE-R1 --+- G0/1 --> L3-CORE        NAT (PAT),
                                  +- G0/2 --> L3-CORE-2       dual transit

        L3-CORE <=== core trunk (G1/0 <-> G1/0) ===> L3-CORE-2
        (active)                                    (standby)

  Each access switch has one uplink to EACH core (dual-homed).
  The access switches do NOT connect to each other.

     SW-ADMIN    -> L3-CORE G0/2  +  L3-CORE-2 G1/2    (V10/20/40/50, F&B on G2/0)
     SW-FLOOR1   -> L3-CORE G0/0  +  L3-CORE-2 G0/0    (APs V30, voice V60, lock V80)
     SW-FLOOR2   -> L3-CORE G0/1  +  L3-CORE-2 G0/1    (APs V30, voice V60, lock V80)

Every switch — and the edge — reaches both cores; the core-to-core trunk carries every VLAN and is the L2 path HSRP peers over. F&B/POS terminals attach to SW-ADMIN on VLAN 50. The exact uplinks:

5 · Four-tier segmentation

Four classes of device, four different policies — the difference between them is the design insight, not a copy-paste.

FromGatewayVLAN 40 (servers)Other internalInternet
Guest (30)✓✗✗✓
Voice (60)✓✓ PBX✗✗
IoT / lock (80)✓✓ lock server✗✗
F&B / POS (50)✓✓ PMS / payment✗✓ card processor

F&B/POS breaks the pattern on purpose. Point-of-sale needs both its PMS/payment server on VLAN 40 and the internet (to reach the card processor), but still no lateral movement. So it's neither "guest" (internet, no LAN) nor "appliance" (LAN, no internet) — it's a fourth policy. In production you'd narrow its internet permit to the processor's address; that's PCI segmentation in miniature.

GUEST-IN — on Vlan30 (internet only)

ip access-list extended GUEST-IN
 permit udp any eq bootpc any eq bootps
 deny   ip any 192.168.10.0 0.0.0.255
 deny   ip any 192.168.20.0 0.0.0.255
 deny   ip any 192.168.40.0 0.0.0.255
 deny   ip any 192.168.50.0 0.0.0.255
 deny   ip any 192.168.60.0 0.0.0.255
 deny   ip any 192.168.80.0 0.0.0.255
 deny   ip any 192.168.99.0 0.0.0.255
 deny   ip any 10.0.0.0 0.0.0.3
 permit ip any any
interface Vlan30
 ip access-group GUEST-IN in

VOICE-IN / IOT-IN — default-deny appliances

ip access-list extended IOT-IN
 permit udp any eq bootpc any eq bootps
 permit ip 192.168.80.0 0.0.0.255 192.168.80.0 0.0.0.255
 permit ip 192.168.80.0 0.0.0.255 192.168.40.0 0.0.0.255
 deny   ip any 192.168.0.0 0.0.255.255
 deny   ip any 10.0.0.0 0.0.0.3
 deny   ip any any
interface Vlan80
 ip access-group IOT-IN in
! VOICE-IN on Vlan60 is identical, swapping 80 -> 60

FB-IN — on Vlan50 (server + payment, no lateral)

ip access-list extended FB-IN
 permit udp any eq bootpc any eq bootps
 permit ip 192.168.50.0 0.0.0.255 192.168.50.0 0.0.0.255
 permit ip 192.168.50.0 0.0.0.255 192.168.40.0 0.0.0.255
 deny   ip any 192.168.0.0 0.0.255.255
 deny   ip any 10.0.0.0 0.0.0.3
 permit ip any any
interface Vlan50
 ip access-group FB-IN in

The order is the whole point: the two permit lines let POS reach its own subnet and the PMS/payment server first, then deny 192.168.0.0/16 blocks every other internal hop, and only after that does permit ip any any let card traffic out. Flip the internet permit above the deny and POS could suddenly reach the guest VLAN.

The classic trap: a guest-isolation ACL on an appliance VLAN denies the appliance its own subnet — the door lock pulls DHCP but can't ping its own gateway, while internet still works because it falls through permit ip any any. Appliances get their own default-deny policy, not the guest ACL.

6 · High availability

HSRP — the floating gateway

Each VLAN gateway is a virtual IP that lives on whichever core is active. Clients never change — they still point at 192.168.x.1. Core-1 .2, Core-2 .3, VIP .1.

track 1 interface GigabitEthernet0/3 line-protocol
interface Vlan50
 ip address 192.168.50.2 255.255.255.0
 standby version 2
 standby 50 ip 192.168.50.1
 standby 50 priority 110
 standby 50 preempt
 standby 50 track 1 decrement 30
! repeat per VLAN (10,20,30,40,50,60,80,99) with matching group numbers
spanning-tree vlan 10,20,30,40,50,60,80,99 priority 4096

track 1 watches the uplink to EDGE. If it drops, the active core's priority decrements by 30 (110 → 80), below Core-2's 90, so the gateway fails over before traffic black-holes — not just when the whole switch dies.

WAN failover (dual transit + tracked static)

ip sla 1
 icmp-echo 10.0.0.2 source-interface GigabitEthernet0/1
 frequency 5
ip sla schedule 1 life forever start-time now
track 1 ip sla 1 reachability
ip route 192.168.0.0 255.255.0.0 10.0.0.2 track 1   ! primary, via Core-1
ip route 192.168.0.0 255.255.0.0 10.0.0.6 10        ! floating backup, via Core-2

A bare static won't fail over — in CML the link stays "up" even when the far node is stopped, so the route never withdraws. IP SLA + a tracked static makes EDGE actively ping Core-1 and pull the route when it stops answering. Remove any old per-VLAN /24 statics — a /24 is more specific than the /16 summary and would never fail over.

Prove the failover

! continuous ping from a client, then fully STOP L3-CORE in CML
show standby brief          ! Core-2 now Active on all VLANs
show ip route 192.168.50.0  ! on EDGE: now via 10.0.0.6
! start Core-1 -> it preempts back to Active; EDGE route reverts

7 · Lessons learned

Every one of these was hit and fixed on live IOS — the kind of troubleshooting that answers an interview question better than a clean config does.

SymptomCauseFix
HSRP split-brain (both cores Active)Default-deny VOICE/IOT ACLs dropped the HSRP hellos (224.0.0.102, UDP 1985)Permit the hellos before the denies
Appliance can't ping its own gatewayGuest-isolation ACL applied to an appliance VLAN denies its own subnetGive appliances their own default-deny ACL
Internet dies on failoverBare static doesn't withdraw when the device dies but the link stays upIP SLA + object tracking
Route won't fail overStale per-VLAN /24 beats the /16 summary (longest-prefix)Remove the stale /24s
Trunk mode rejectedEncapsulation set after mode on IOSvL2switchport trunk encapsulation dot1q first
